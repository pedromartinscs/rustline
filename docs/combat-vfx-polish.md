## Damage and visual lifetime

The bomb caches shared sprite/material references at launch. On contact it disables its flight LineRenderer, creates one sprite child, shows key zero, then applies the original damage call immediately. `HasExploded` guards the existing one-shot path; subsequent FixedUpdates perform no trajectory sweep or damage and wait only for the visual to finish. Six keys run at nominal 0.06 s each; the flash is held for the detonation render frame. Completion hides the sprite and the next fixed step destroys/unregisters the spent bomb. There is no second visual timer in combat.

The child stays owned by the same bomb list used by retry, checkpoints, restart and completion. Cancellation synchronously hides both flight/body and explosion before deferred root destruction. Creating the visual before damage is deliberate: a lethal player hit may synchronously respawn/reset and cancel that very bomb. No new effect is created after that callback. Disabling an in-progress visual marks it complete, preventing a retained spent-bomb leak. Scene unloading destroys the root and child together. Sprite frames and material are shared; no runtime pixel manipulation, material cloning, global discovery loop or effect framework was added.
